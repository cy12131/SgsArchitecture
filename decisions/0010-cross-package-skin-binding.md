# ADR-0010: 独立皮肤包跨资源包绑定武将

- 状态：Accepted（能力要求）；接口形状为 Draft
- 日期：2026-10-25

## Context

皮肤、技能语音、阵亡语音和动画需要独立于武将规则演进。若只能修改原武将包或在 SgsClient/SgsServer 中增加专用分支，每次美术扩展都会耦合规则发布和框架升级，也无法让武将包与皮肤包独立锁定及回滚。

## Decision

SGS 必须支持独立皮肤资源包通过稳定的跨包武将 ID，为另一资源包已经注册的武将增加皮肤、技能语音、阵亡语音和动画。绑定不得修改原武将包，也不得要求 SgsServer/SgsClient 为特定武将或皮肤编写专用代码。

武将包与皮肤包使用独立 Git 仓库，并分别锁定 commit。皮肤包在 `manifest.json` 中声明对目标武将包的依赖，依赖拓扑保证武将先注册。通用扩展层未来提供 GeneralRegistry、SkinRegistry 和 ResourceResolver 概念能力；具体符号、参数和数据格式保持 Draft。

同一启动 generation 内，目标武将 ID 必须稳定且可无歧义查询。皮肤注册必须记录 owner package 并检测 ID 冲突；不允许通过文件覆盖、目录扫描或“最后加载者获胜”扩展其他包。资源缺失时安全回退到目标武将默认立绘/语音，必要时再使用框架占位资源。

所有注册和资源解析只使用 SgsServer 启动时锁定的 package generation。添加、更新、启用或停用皮肤包遵循 ADR-0009，正常重启后才生效。

## Consequences

- 美术与语音内容可以独立发布、锁定、停用和回滚，不需要修改权威规则包。
- Manifest 依赖、拓扑加载、owner 信息和冲突拒绝成为跨包扩展的安全边界。
- 禁用皮肤包并正常重启后，其注册项消失，武将恢复默认资源；不会热卸载当前页面或对局资源。
- 框架需要通用 Registry/Resolver 扩展点，但不拥有具体武将、皮肤或动画实现。

## Deferred

本 ADR 不冻结武将 ID 或皮肤 ID 的命名语法、皮肤文件命名、技能语音映射、动态皮肤格式、Registry 方法签名、QML 类型或皮肤选择持久化协议。这些内容需在 M3-C 用真实双仓库样例验证后另行评审。
